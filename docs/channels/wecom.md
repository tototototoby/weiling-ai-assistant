# 企业微信通道

微Link通过企业微信 Bot 的 WebSocket/长连接方式接入。它适合团队入口和主动投递，但需要管理员在企业微信侧创建应用/机器人并完成授权，项目不提供官方凭据。

## 你会得到什么

- 员工在企业微信里和指定 Bot 对话；
- 管理员把员工身份绑定到已有的微Link Bot；
- 同一 Bot 的工作区、记忆和任务可以与其他已配置入口衔接；
- 需要主动提醒时，Supervisor 通过长连接尝试投递并记录回执。

## 前置条件

- 企业微信管理员权限或已由管理员创建的 Bot；
- 企业微信 Bot ID、Secret 和平台提供的 WebSocket 地址/配置；
- 微Link Web、Supervisor 正常运行；
- 管理员已准备受控测试员工账号；
- 服务器可以建立出站 WebSocket 连接。

具体字段名称随企业微信控制台版本变化，以官方文档和当前管理页为准，不要把示例值当成真实凭据。

## 配置步骤

1. 在企业微信管理台创建或选择 AI Bot，开启 Bot API/WebSocket 能力。
2. 在微Link管理员页面打开企业微信配置，填写 Bot ID、Secret 和连接地址。
3. 保存后观察连接状态：disabled → connecting → connected。
4. 使用测试员工账号给 Bot 发：

   ```text
   请回复“企微通道已连接”，不要调用工具。
   ```

5. 在 Bot/员工绑定页完成员工身份与 Bot 的绑定。
6. 再发送一个无副作用任务，检查入站、回复和投递回执。

## 员工绑定与隔离

企业微信通常是一个全局 Bot 连接，员工身份由微Link绑定到各自 Bot。一个员工不应因为名字相同而被路由到别人的 Bot；绑定前先确认企业微信用户 ID、显示名和目标 Bot。

每个员工的会话、模型配置、实例目录和沙箱工作区应该保持隔离。管理员可以看到管理数据，但不应把所有员工的聊天内容复制到群消息或演示图中。

## 主动投递

主动提醒依赖三件事：

1. Supervisor 与企业微信 WebSocket 保持连接；
2. 当前员工仍有有效的 Bot 绑定；
3. 企业微信侧允许该类消息和内容。

微Link会为投递记录状态和幂等键，遇到 processing/failed 时先查看记录和日志。不要因为没有收到一条消息就马上重复创建同一提醒。

## 故障排查

| 现象 | 排查 |
| --- | --- |
| 一直 connecting | 检查 Bot ID/Secret、WS 地址、出站网络和企业微信侧开关。 |
| 消息能收到但回复失败 | 检查模型配置、Supervisor 日志和消息格式。 |
| 员工未绑定 | 使用平台稳定的用户 ID，不用昵称猜测；重新执行绑定流程。 |
| 主动消息失败 | 检查连接、绑定、平台限制和投递回执。 |
| 重启后配置丢失 | 检查 SQLite、`lark`/secrets 与生产数据根目录是否持久化。 |

## 安全提醒

Secret 只写入权限受限的运行配置。不要把企业微信应用 ID、Secret、员工 ID 或真实回执上传到 Issue；安全问题请按 [SECURITY.md](../../SECURITY.md) 报告。
