# 微信通道

这篇教程说明如何把一个 Bot 接入微信并完成最小收发验证。微信侧登录态、可用时长、主动消息和媒体能力受平台与运行时版本影响，请把真实 E2E 结果当作最终判断。

## 适用场景

- 想从微信里直接给微Link发文字、语音或文件；
- 想在聊天窗口里领取一个已分享的 Bot；
- 想把需要等待的工作交给服务端继续处理。

## 前置条件

- Web 和 Supervisor 已启动；
- 至少一个用户已创建模型配置；
- Bot 已创建并绑定模型；
- 手机微信可以扫描页面二维码；
- 部署服务器能访问模型网关和需要使用的外部服务。

## 连接步骤

1. 在 Web 控制台创建或打开一个 Bot。
2. 点击启动，等待状态进入扫码或等待登录。
3. 用微信扫描页面中的临时二维码并在手机上确认。
4. 等待页面显示已登录/运行中。
5. 先发送：

   ```text
   请只回复“微信通道已连接”，不要调用工具。
   ```

6. 再发送一个无副作用的 Skill 查询，确认工具链已加载。

如果你只想在命令行验证 FastAgent 通道，运行时通常使用：

```bash
fastagent --channel weixin --output jsonl
```

命令行验证需要单独准备模型和运行时变量；长期多用户运行请使用 Web + Supervisor。

## 二维码与登录态

- 只信任控制台返回的二维码，不要在聊天中转发真实二维码图片。
- 二维码可能过期；先点击重新出码，再扫码，不要重复使用旧截图。
- 登录态落在 Bot 实例目录，实例目录和 SQLite 必须纳入权限受限的备份。
- 换服务器或改数据根目录前，先完成迁移和回滚演练，避免生成一个空 Bot。

## 主动消息的现实限制

微信 iLink/相关登录态可能对长时间没有对话后的主动消息施加限制。微Link可以持久化任务和投递状态，但不能绕过微信侧策略；如果超过平台允许的时间没有互动，主动消息可能失败。

建议为重要任务配置企业微信或飞书补充入口，并在 [共享上下文](../shared-context.md) 中验证它们是否路由到同一个 Bot。不要把“服务端任务仍在运行”误写成“微信一定能主动送达”。

## 文件与语音

语音识别、文件下载、文件回传和生成图片依赖 FastAgent 版本、模型和通道能力。测试时使用空白文件和虚拟素材；不要上传客户资料或包含密钥的文件。发送文件前确认工作区相对路径和目标聊天，长任务超时后先询问状态，不要重复提交。

## 常见问题

| 现象 | 排查 |
| --- | --- |
| 页面没有二维码 | 看 Web/Supervisor 日志；确认 Bot 已启动并没有处于退避重启。 |
| 扫码后很快掉线 | 检查微信登录态、网络、运行时版本和实例目录权限。 |
| 回复正常但主动提醒失败 | 查看平台侧主动消息限制、通道绑定和投递回执；必要时用企微/飞书补充。 |
| 生成文件后没有收到 | 确认文件标记、工作区路径和通道媒体能力；不要声称“已发送”而没有回执。 |
