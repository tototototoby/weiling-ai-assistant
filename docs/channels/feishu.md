# 飞书通道

飞书接入通过 `lark-cli` 和飞书应用权限完成。微Link可以提供私聊、群聊、文件和一组 Lark Skills 的接入路径，但最终能力由飞书应用版本、事件订阅、用户授权和群权限决定。

## 前置条件

- 飞书开放平台应用的 App ID 和 App Secret；
- 已打开所需事件订阅、消息和资源权限；
- 部署环境安装可用的 `lark-cli`；
- Web、Supervisor 和 Bot 已创建；
- 一个专用的测试用户/群，避免拿生产群做首次验证。

可以在环境中检查 CLI：

```bash
lark-cli --version
```

如果路径不同，使用 `WECLAWS_LARK_CLI_PATH`（当前运行时兼容项）指向实际可执行文件。

## 配置步骤

1. 在飞书开放平台创建企业自建应用。
2. 按需申请消息、群聊、文件、文档、日历或其他 Skill 所需权限。
3. 在微Link管理员页面打开飞书配置，填写 App ID 和 Secret。
4. 完成 `lark-cli` 的应用授权，并确认配置写入持久化的 Lark 配置目录。
5. 为 Bot 启用飞书通道。
6. 先在测试私聊发送：

   ```text
   请回复“飞书通道已连接”，不要调用工具。
   ```

7. 如需群聊，再把应用加入测试群并验证群权限、群上下文和文件回传。

## 私聊与群聊的边界

- 私聊回复只面向当前用户；群聊回复只面向当前群成员。
- 群聊中不要引用任何私聊上下文，也不要调用微信或其他通道的发送工具。
- 生成要发到私聊或群里的文件时，运行时会使用通道约定的文件标记；只有收到成功回执后才能向用户说“已发送”。
- 收到群文件时，先验证文件名、路径和大小，避免把绝对路径或宿主机信息写进回复。

## Skills 与权限

`lark-*` Skills 不是凭据，也不是飞书权限的替代品。每个 Skill 需要：

- 它在 Bot 实例中已经同步；
- 容器中存在 `lark-cli`；
- 飞书应用具备对应 scope；
- 应用授权仍有效；
- 任务内容符合企业内部权限与保密规则。

先用只读请求验证：

```text
请读取我有权限看到的一个测试文档标题，不要编辑、分享或发送。
```

确认读取正常后，再显式确认任何写入、移动、删除或发送操作。

## 常见问题

| 现象 | 排查 |
| --- | --- |
| `lark-cli` 找不到 | 检查安装、PATH 和 `WECLAWS_LARK_CLI_PATH`。 |
| 私聊没回复 | 检查 App ID/Secret、事件订阅、Supervisor 日志和 Bot 配置。 |
| 群聊没回复 | 确认应用已加入群、机器人权限和群事件已开启。 |
| 文档/日历 Skill 被拒绝 | 查看缺少的 scope 和用户授权，不要用另一个人的 Token 代替。 |
| 文件回传失败 | 检查工作区相对路径、文件大小、飞书文件权限和通道标记。 |

飞书应用的 Secret、OAuth 状态、用户邮箱和群 ID 都属于敏感信息，截图和日志发布前必须脱敏。
