# 共享上下文：一件事可以在多个入口继续

微Link想解决的不是“把所有聊天混成一锅”，而是让同一个用户交给同一个 Bot 的任务能够跨入口继续，同时保留不同平台的身份、权限和发送规则。

## 什么会共享

在通道配置、Bot 绑定和运行时会话键都正确时，以下内容可以共享：

- 任务目标和已确认的约束；
- Bot 已保存的记忆和工作区文件；
- 任务执行状态、产出文件和下一步；
- 主动提醒需要引用的目标与投递状态。

例如：

1. 微信：“周五下午做一张活动海报，风格清爽。”
2. 路上离开微信，改在飞书私聊：“把标题改成春日茶歇。”
3. 回到 Web 查看生成的海报和执行日志。

这不是把微信聊天记录直接复制到飞书，而是让入口路由到同一个 Bot 的会话/工作区。

## 什么不会共享

- 不同用户的会话、模型 Key、文件和沙箱工作区；
- 没有绑定到同一个 Bot 的两个机器人；
- 平台的原始身份、群成员权限和发送能力；
- 被通道策略禁止的工具。例如飞书群聊不应调用微信发送工具；
- 某些平台只允许在用户先说话后回复，不能因为共享上下文就绕过平台政策。

## 配置检查顺序

1. 确认两个入口实际绑定同一个 Bot，而不是名字相似的两个 Bot。
2. 确认 Bot 的模型配置和工作区路径没有在迁移中漂移。
3. 检查 Supervisor 日志里身份路由、session key 和 Bot ID。
4. 用一个无敏感信息的唯一短语测试，例如 `context-check-2026-01`。
5. 分别从两个通道询问该短语；失败时保存脱敏日志，不要反复发送真实任务。

## 平台差异

### 微信

微信 iLink/登录态的可用时长和主动消息能力受平台侧策略影响。若长时间没有对话后主动消息受限，不要把“共享上下文”理解成可以绕过限制；可为同一个 Bot 配置企业微信或飞书作为补充入口。

### 企业微信

企业微信入口通常由管理员配置一个 Bot，再将已验证的员工身份绑定到自己的 Bot。员工之间不共享个人会话；主动投递需要有可用绑定和在线 WebSocket 连接。

### 飞书

飞书可以接入私聊和群聊，但权限、事件订阅、群内发送和文件回传都由飞书应用配置决定。群聊上下文应当以群为边界，不要把私聊内容带进群回复。

## 排障提示

如果跨端看不到前一条消息，优先排查路由和身份，不要先清库：

- Bot ID 是否一致；
- 通道授权是否属于同一个部署；
- `APP_BASE_URL` 和反向代理是否把入口带到了另一台实例；
- 数据库是否使用了不同的挂载目录；
- 实例目录是否因改名迁移变成了新空目录。

安全边界和数据留存见 [安全模型](security-model.md)。
