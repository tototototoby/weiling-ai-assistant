# 教程：让微Link主动跟进

微Link的“会跟进”不是到点弹一下就结束，而是把目标、提醒时间、当前状态和下一步保留下来。收到你的回复后，它再根据最新信息整理下一步。

## 预期结果

创建一个不会产生外部副作用的提醒，收到提醒后回复进展，验证任务和投递状态都能在服务端持续保存。

## 前置条件

- Bot 已运行；
- 目标通道已授权，并且该通道允许对应的主动消息；
- Supervisor、SQLite 和实例目录已持久化；
- 服务器时区、系统时间和计划时间正确。

## 发送示例

```text
请记住：明天上午 10 点提醒我确认“春日茶歇海报”。
提醒时先问我“海报定稿了吗？”，如果我回复还没定稿，请帮我列出下一步，不要替我发送给任何人。
```

如果平台/运行时支持会话级定时任务，微Link会创建任务并在合适的时间尝试投递。确认创建结果后，先不要重复发送同一条指令。

## 到时间之后

你可能收到类似：

```text
到时间啦：海报定稿了吗？如果还没有，我可以帮你列出下一步。
```

你可以回复：

```text
还没有，先给我列三个最重要的检查项。
```

微Link应该把这个回复作为同一任务的进展，而不是新建一个无关任务。检查它是否返回了清单、更新后的状态和下一步。

## 失败时怎么判断

主动投递可能因为以下原因失败：

- 通道连接断开或 Bot 绑定不存在；
- 平台只允许在用户最近互动后回复；
- 平台应用没有主动消息权限；
- Supervisor/数据库/投递队列不可用；
- 任务时间和服务器时区不一致。

到时没有收到消息时，先在 Web、Supervisor 日志或管理页查看投递记录。任务仍可能在后台运行，不要立刻复制同一提醒。

## 验收清单

- [ ] 创建任务后重启 Web，任务仍存在；
- [ ] 重启 Supervisor 后任务不会无条件重复投递；
- [ ] 投递有明确的 sent/failed/processing 状态；
- [ ] 失败原因能指导修复；
- [ ] 回复进展后，微Link能引用原目标并给出下一步；
- [ ] 两个用户的提醒不会交叉；
- [ ] 只有在通道允许且绑定有效时才尝试主动发送。

## “多一份提醒，多一份安心”

主动提醒不是替你做决定，也不是强行打扰。把它当作一个可取消、可追踪的轻量协作者：少忘一件事，多一份提醒，多一份安心。
