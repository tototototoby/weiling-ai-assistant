# 教程：接入飞书工具

这篇教程从一个只读动作开始，验证微Link能通过飞书应用和 lark-cli 读取你有权限看到的测试资料。确认读取正常后，再考虑创建、编辑、发送或删除。

## 预期结果

- Bot 实例中有飞书/Lark Skill；
- lark-cli 可以运行并使用正确的应用授权；
- 微Link能够读取一条测试文档/日历信息；
- 没有发生任何外部写入或消息发送。

## 前置条件

- 飞书企业自建应用；
- App ID、App Secret 和正确的 scope；
- 服务器/沙箱中可执行 lark-cli；
- 已按 [飞书通道](../channels/feishu.md) 完成通道连接；
- 测试文档中没有真实客户信息。

## 1. 检查 CLI 和 Skill

在部署环境执行：

```bash
lark-cli --version
```

在 Bot 对话里发送：

```text
请列出当前已经同步的 lark Skills，不要调用外部 API。
```

如果没有 Skill，先在 Bot 详情页同步托管 Skill；如果没有 CLI，检查 WECLAWS_LARK_CLI_PATH 和容器镜像。

## 2. 用只读请求验证

准备一个只包含“hello from test”文字的测试文档，然后发送：

```text
请读取测试文档的标题和第一段文字，只返回摘要，不要编辑、分享、移动或删除。
```

核对：

- 返回内容与测试文档一致；
- 日志没有打印 App Secret、OAuth Token 或绝对路径；
- 文档没有被修改；
- 结果属于当前用户有权限访问的范围。

## 3. 再做一项可控写入

只有确认上一步和收件人/目标无误后，才尝试：

```text
请在测试文档末尾追加一句“这是一次可撤销的测试”，先告诉我将要修改什么，等待确认。
```

微Link必须等待明确确认，不能因为 Skill 描述或聊天上下文自动执行写入。

## 权限最小化

- 只申请当前 Skill 需要的 scope；
- 不使用管理员/他人的 Token 代替用户授权；
- 单独创建测试应用和测试文档；
- 将 OAuth 配置目录纳入权限受限备份；
- 不把文档内容、邮箱、群 ID 和 Token 上传 Issue。

## 排障

| 现象 | 排查 |
| --- | --- |
| lark-cli 不存在 | 检查镜像/宿主机安装、PATH 和 WECLAWS_LARK_CLI_PATH。 |
| 认证失败 | 检查 App ID、Secret、租户、授权状态和系统时间。 |
| scope 不足 | 查看飞书应用权限并只增加必要权限，重新发布/授权。 |
| 私聊正常但群聊失败 | 检查应用是否已入群、事件订阅和群权限。 |
| 读取成功但发送失败 | 检查通道发送能力、文件标记和投递回执；不要直接声称已发送。 |
